# 使用与签名说明

> 本仓库**只发源码，不发预编译包**。原因见最后一节：鸿蒙的开发签名把证书绑定在签名人自己的设备上，别人拿到 HAP 也装不上。

---

## 0. 三个部件

| 部件 | 位置 | 作用 |
|---|---|---|
| 电脑端插件 | `bridge/` | 装在 DSH 里：反代 DSH Web、发配对二维码、体检、守护 Cloudflare 隧道 |
| 鸿蒙客户端 | `app/` | ArkTS 写的手机 App，全屏 WebView + 回合结束通知 |
| 安卓客户端 | `android/` | 纯 Java，命令行构建，同样全屏 WebView + 通知 |

三者都**不理解 DSH 协议**——手机只是把 DSH 的网页装进 App，桥负责把网页送出去、把「回合结束」事件变成通知。

---

## 1. 电脑端：装桥插件

1. 克隆仓库：

   ```powershell
   git clone https://github.com/uchiha086/dshremote.git
   cd dshremote
   ```

2. 把 `bridge/` 装进你的 DSH profile。最省事的做法是在 DSH 里对 Agent 说一句：

   > 用 plugin_manager 的 install_bundle 安装 `C:\path\to\dshremote\bridge` 这个本地目录，然后告诉我装完要重启。

   也可以手动等价操作：把该目录 link 进 `<profile>/node_modules/dshremote-bridge`，并在 profile 的 `package.json` 里给 `dsh.profile.bundles` 加上 `dshremote-bridge`。

3. **重启 Desktop**（插件是进程内加载，不重启不生效）。

4. 验证桥活着：

   ```powershell
   curl.exe http://127.0.0.1:3088/health
   # {"ok":true,"service":"dshremote-bridge","version":"0.2.0","protocol":1,...}
   ```

5. 打开 DSH，左下角设置按钮旁边会多一个二维码图标 —— 点开就是配对面板。

桥的端口：`3088`（桥自身 + 面板 API）、`7627`（DSH Web 的反代）、`3089/UDP`（局域网自动发现的广播）。

## 2. 鸿蒙端：编译 + 用你自己的账号签名

### 2.1 前置

- DevEco Studio（本仓库在 **26.0.1.290 / API 26** 上验证通过）
- 一台 HarmonyOS NEXT 设备（API 26），开启「开发者模式 + USB 调试」
- 华为账号（个人账号即可，免费）

### 2.2 生成你自己的签名（只做一次）

1. DevEco 打开 **`app/` 目录**（不是仓库根目录）。
2. 登录华为账号（右上角头像）。
3. 插上手机，等 IDE 识别到设备。
4. `File → Project Structure → Signing Configs` → 勾选 **Automatically generate signature** → `Apply`。

   此时 DevEco 会在 `~/.ohos/config/` 生成 `.p12 / .cer / .p7b`，在工程内生成 `.sign/sign-config.json5`，**并把你这台设备的 UDID 写进 profile 的 `debug-info.device-ids`**。

### 2.3 构建（不用开 IDE 也能跑）

```powershell
$env:DEVECO_SDK_HOME = 'E:\dev\DevEco Studio\sdk'      # 换成你的安装路径
cd app
& 'E:\dev\DevEco Studio\tools\hvigor\bin\hvigorw.bat' assembleHap `
    --mode module -p product=default -p buildMode=debug --no-daemon
```

产物：`app/entry/build/default/outputs/default/entry-default-signed.hap`

### 2.4 装到手机

```powershell
hdc install -r app\entry\build\default\outputs\default\entry-default-signed.hap
```

或者直接在 DevEco 里点 Run。

### 2.5 必须知道的限制

- 这个 HAP **只能装到「签名时 profile 里登记过 UDID」的设备上**。换手机、给别人装，一律要重签。
- 调试证书有效期 **1 年**（你可以在 `~/.ohos/config/*.p7b` 里看到 `validity`），到期重做 2.2 即可。
- 包名默认是 `com.example.myapplication`（为了兼容 DevEco 通用调试证书）。想改成自己的：改 `app/AppScope/app.json5` 的 `bundleName`，然后**重做 2.2 的自动签名**（新包名要有新 profile）。
- 一个华为账号的调试设备上限是 100 台。

## 3. 安卓端：编译 + 签名

### 3.1 前置

- JDK 17 或更高（DevEco 自带的 JBR 也行）
- Android SDK：`build-tools;34.0.0` + `platforms;android-34`

### 3.2 构建

```powershell
cd android
& .\build.ps1 -Sdk 'C:\Users\you\android-sdk' -Jdk 'C:\Program Files\Java\jdk-21'
```

脚本会依次跑 `aapt2 compile → aapt2 link → javac → d8 → 塞 classes.dex → zipalign → apksigner`，全程不需要 Gradle，也不需要任何第三方依赖。

产物：`android/dshremote-android-0.2.0.apk`

### 3.3 用自己的 keystore（可选）

不传参数时脚本会自动生成 `android/debug.keystore`（alias / 口令都是 `dshremote`）。想用正式签名：

```powershell
& .\build.ps1 -KsPath 'C:\keys\my-release.jks' -KsAlias mykey `
              -KsPass '你的storepass' -KsKeyPass '你的keypass'
```

### 3.4 安装

```powershell
adb install -r android\dshremote-android-0.2.0.apk
```

或者把 APK 传到手机、允许「安装未知来源应用」后直接点装。安卓的 debug 签名**不绑定设备**，给谁都能装（上架应用商店才需要 release key）。

## 4. 第一次配对

1. 电脑端桥已装好、Desktop 已重启。
2. DSH 左下角点二维码图标 → 面板会先跑**五项体检**：

   | 检查项 | 含义 |
   |---|---|
   | 桥服务 | 桥进程在不在 |
   | DSH 反代 | 7627 能不能打到 DSH |
   | 局域网可达 | 手机能不能用 `http://<你的IP>:3088` |
   | 隧道 → 桥 / 隧道 → DSH | 公网域名是否还活着 |

   全绿才出码；没通过时面板会给出原因和「一键修复」「让 AI 修」两个按钮。

3. 手机 App 点「扫码连接电脑」扫这个码 → 自动填地址与令牌 → 直接进 DSH 全屏界面。
4. 右上角只有一个齿轮，点开是设置/重新配对。

**出门在外**（不在同一个 Wi-Fi）：电脑上跑

```powershell
tools\tunnel.ps1
```

它会拉起 `cloudflared` 快速隧道、登记域名、把公网地址写进二维码。注意：快速隧道每次重启域名都会变，且 Cloudflare 有每小时配额，长期用建议换成命名隧道 + Access（见 Roadmap）。

## 5. 常见故障

| 现象 | 原因 / 处理 |
|---|---|
| 体检「隧道 ✗」 | cloudflared 没起来或被限流 → 点「一键修复」；仍失败就重启 Desktop |
| 扫码后 `operation timeout` | 电脑休眠/断网、或二维码里是过期的隧道域名 → 重新出码 |
| 打开白屏 / 提示 `authentication required` | cookie 注入失败 → App 里点齿轮「保存并进入」重连 |
| 手机通知不弹 | 安卓要授予通知权限；鸿蒙首次启动要点「允许」，之后在系统设置里确认未被禁用 |
| 鸿蒙构建报 `00303024` | `hvigor/hvigor-config.json5` 与根 `oh-package.json5` 的 `modelVersion` 不一致 |
| 鸿蒙构建报 `00306042` | `compatibleSdkVersion` 写法与 SDK 版本不匹配（API ≥ 26 用 `"26.0.0"` 形式） |
| 安卓构建报 `missing tool` | `-Sdk` / `-Jdk` 指错了 |

更多细节见 [使用说明.md](使用说明.md) 与 [开发计划.md](../开发计划.md)。

## 6. 为什么仓库不发二进制

鸿蒙的调试签名文件（`.p7b`）里有一段 JSON，长这样：

```json
{
  "type": "debug",
  "bundle-info": { "bundle-name": "com.example.myapplication" },
  "debug-info": {
    "device-id-type": "udid",
    "device-ids": ["302E4113……（只有签名人那一台）"]
  },
  "validity": { "not-before": 1795154492, "not-after": 1826690492 }
}
```

安装时系统会拿**目标设备的 UDID** 和这个数组比对，不在列表里就直接拒绝（表现为签名/Profile 校验失败，而不是「包损坏」）。所以：

- 你自己编译 + 自己签名 → 能装；
- 下载别人的 HAP → 装不上；
- 同一账号的另一台手机 → 也要重新签名（把 UDID 加进 profile）。

**想公开发布给陌生人**，正路是走华为 AppGallery Connect：

1. AGC 创建应用（包名换成你自己的，例如 `com.uchiha086.dshremote`）；
2. 上传 HAP，选择「开放式测试 / 内部测试 / 正式上架」；
3. 补齐隐私政策、应用截图、分类等信息，提交审核；
4. 审核通过后用户从应用市场安装，**不再受 UDID 限制**。

安卓没有这个限制——debug 签名的 APK 谁都能装，只是别用 debug key 上架。
